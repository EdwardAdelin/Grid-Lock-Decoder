# Grid-Lock-Decoder
Using the famous "NYC Taxi Trip Data" (which has billions of rows detailing pickup/drop-off times and locations), I wrote a Hadoop job to find the absolute worst hours of the day to travel between specific city zones, based on average trip duration.

# What is a Hadoop project and why we built this one?

#### Standard tools read data sequentially (one line at a time). If I tried to process 10 million taxi records in Python on a single processor, it would cause a bottleneck and potentially run out of memory.

#### This is a *Hadoop project* because it relies on Distributed Storage (HDFS) and Distributed Processing (MapReduce). 

HDFS takes the massive 1.5GB CSV file and splits it into smaller blocks (in our case, 13 splits) across the cluster. Then, instead of moving the massive dataset to the processor, Hadoop moves the computation to where the data lives (Data Locality). 

#### This proves the concept of Horizontal Scalability. If I wanted to process 1 billion rows, I wouldn't need a bigger supercomputer; I would just add more cheap nodes to the cluster.

# Data flow

#### 1. The Input Split (The Parallelism)
The 10 million-row CSV is split into 13 chunks. Hadoop spins up 13 parallel "Workers" to read these chunks simultaneously.

#### 2. The Map Phase (Extraction)

Every worker executes the Java TaxiMapper code line by line.

    Input: A raw string of text (e.g., 1,2016-01-01 08:15:00,2016-01-01 08:45:00,5.00)

    The Logic: The code parses the dates, extracts just the Hour (08:00), and calculates the trip duration in minutes (30.0).

    Output: It spits out a Key-Value pair: [Key: "08:00", Value: 30.0]

#### 3. The Shuffle and Sort Phase (The Magic)
This happens automatically in the background. Hadoop takes all the millions of Key-Value pairs generated by the 13 Mappers and sorts them across the network. It guarantees that every single value with the exact same Key goes to the exact same Reducer.

    All the 08:00 durations are routed to Reducer A.

    All the 17:00 durations are routed to Reducer B.

#### 4. The Reduce Phase (Aggregation)
The Java AverageReducer code receives a single Key, alongside a massive list of all the values associated with it.

    Input: [Key: "08:00", Values: (30.0, 15.0, 45.0, 12.0...)]

    The Logic: The Reducer loops through the list, adds up the total minutes, and divides by the total count to find the average.

    Output: [Key: "08:00", Value: 40.5]
